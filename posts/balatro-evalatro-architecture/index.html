TL;DR
#

Evalatro 用真实 Steam 版 Balatro 给 LLM 排名，榜单头部模型平均只推进到 Ante 5，至今没有任何模型拿到 winRate。我们拆开这个天花板后发现：其中相当一部分不是模型能力上限，而是评测架构的上限——无记忆的单局设计让每一局 40-90 分钟的经验全部蒸发，而官方构建没有开启 endless,通关 Ante 8 之后对局就地结束，没有人能冲击 targetAnte 12 的分数上限。把评测场改造成"训练场"、并补上 endless 这条路之后，同一个模型(gemini37-flash-high)的训练局均分从 18.7 爬到 81.0,并打出了整个项目历史上第一局打到 Ante 12 的对局(score 99.8)。

1. 榜单现状：全员卡在 Ante 5
#

Evalatro 的玩法很硬核：模型通过 balatrobot(一个挂在游戏进程里的 HTTP/JSON-RPC mod)驱动真实游戏客户端，每一步都拿到带迷雾遮挡的状态(对手牌型可见、牌堆只看到 “?”),然后从 12 个动作工具里选一个执行。评分公式:

score = progress × legality × 100

progress 按盲注阶梯位置除以 targetAnte(=12)折算，legality 按非法操作率扣分，通关需要打到 Ante 13。

winRate 一列全是 0。 头部模型平均死在 Ante 4-5(Balatro 的难度曲线在 Ante 4 后陡增：盲注要求翻倍，“随便打打"的牌型组合开始不够用)。样本最多的 DeepSeek-V4-Flash 最好打到过单局 Ante 8——那其实已经是通关了基础游戏；但官方构建没有开启 endless,赢下 Ante 8 Boss 后游戏弹出胜利画面，对局就地结束、在榜上记为 stuck。通关线之外没有路：winRate 按 ante≥13 判定，所以全员为 0,分数也被压在通关线附近。

这个画面很容易被解读成"LLM 玩 Balatro 就是菜”。但我们认为这个解读漏了一半。

2. 诊断：Ante 5 之上立着三道墙
#

通读 Evalatro 和上游 balatrobot 的源码之后，我们把"卡 Ante 5"拆成了三道墙。只有第一道是模型自己的。

墙一：无记忆，每局都是失忆开局
#

适配器每一步只发 system + user 两条消息，没有任何对话历史。通读源码可以确认：唯一的跨回合连续性是 Decision.notes——一个不超过 1200 字符的字符串，由主循环回传给下一步。跨局？没有。上一局学到的任何东西，下一局开局时都不存在。

这意味着：

  • 一局 40-90 分钟、约 66 万 token 的决策与代价，局末全部蒸发;
  • 模型在 BENCH01 里用一整局的代价搞明白"Banner(剩余弃牌数给筹码)和 Mail-In Rebate(弃牌给钱)是互斥的"，下一局它还会照样把这两个小丑牌凑在一起；
  • benchmark 测的是"模型带着出厂知识能走多远"，而不是"模型在一个持续存在的世界里能积累多少"。

后者才是我们关心的能力。人类玩家也不是天生会玩 Balatro 的——是死了十几局之后学会的。

墙二：通关之后的断头路
#

Evalatro 的 targetAnte 是 12,评分上限要求打进 endless 模式。但官方构建没有开启 endless:赢下 Ante 8 Boss 后游戏调用 win_game() 弹出胜利画面，对局就地结束(榜上记为 stuck)。换句话说，打到 Ante 8 的局已经是通关，但"点击 Continue 进 endless 继续冲 Ante 9-12"这个纯 UI 操作，没有任何 agent 实现过。

于是榜单的 winRate 全员为 0、高分无人认领——不是"没人有能力赢"，是"赢了之后没路走"。我们的第一局本机基线(无记忆，mimo-v2.5)死在 Ante 5 Boss 差 31% 筹码,score 40.0,和公共榜第一梯队同水位，说明链路正常，卡的就是上面的东西。

墙三：思考模型被超时机制惩罚
#

思考型模型单步思考量的方差极大——同一 prompt 两次运行，思考 token 可以从 545 涨到 2672,“偶尔一步三分钟"的長尾就是它。而适配器默认的请求超时是 120 秒：超时的步骤被 abort 后重试，token 双倍消耗，还打断模型的思考节奏。榜单上那些 3-6% 的非法率里，有一部分是模型在被反复打断后仓促出手造成的。

3. 换一个问题：不比模型，比记忆
#

三道墙里，墙二墙三都是工程，墙一是架构设计。修掉工程问题只能让分数回到"真实水平”，要打破"真实水平"本身，得把墙一拆了。

所以我们换了个问法。Evalatro 问的是"哪个模型更会玩"；我们想问的是"同一个模型，配上哪种记忆组件，进步更快"：

固定模型、固定轮数，把记忆组件做成可插拔的——模型从一段真实的游戏中获取经验并沉淀，后续调用时按照经验行事。

这就是 Memory Arena。评测场从"考场"变成了"训练场"。

4. 改了什么
#

4.1 记忆管道：反思 → 整合 → 召回
#

挂载点选在适配器的 buildChatPayload()——这是每回合请求的唯一构造点，注入对模型完全透明。管道三段:

反思(Reflect):每局结束，把整局的动作轨迹、最终阵容、胜负原因喂给 LLM,产出一篇结构化复盘。真实产出长这样(节选自一局失利的反思):

“Major strategic blunder: I mismanaged joker positioning, accidentally placing Campfire, which provides xMult, at the beginning of the joker order… Discarding too frequently hurt Ramen’s xMult multiplier… Straights are too hard to draw without deck fixing.”

整合(Consolidate):每个训练局结束立刻整合，不等轮末 barrier。反思账本 append-only,整合时全量重进 LLM 重建攻略。为了避免双车道同时整合互相覆盖，LLM 调用放在锁外，锁内只做毫秒级 CAS 写，冲突重试一次。攻略按"常见错误 / 前期 / 中期 / Boss 盲 / 关键教训"分节，随局数演进——第一版 1368 字符，八局之后长到 2527 字符。

召回(Recall):开局一次 + 每个 ante 检查点一次，把攻略(和记忆组件补充的内容)注入 prompt。runs.memoryVersion 记录局初用的攻略版本，局中检查点会拉到并行车道中途发布的新版本——这是特性：先结束的局发布的新攻略，马上就能被还在打的局用上。

4.2 打通 endless：autoendless
#

墙二的解法是一个自写 mod:evalatro_autoendless,monkey-patch 游戏的 win_game(),在胜利画面弹出 2 秒后自动替所有对局点下 endless 按钮。

这一段的排查过程值得压缩成一段写下来，因为它典型地展示了"游戏 mod 开发的地雷密度":初版三个 bug 让它整整两晚不生效——① 判断 UI 元素用了错误的字段路径，正确姿势是按 id 找 UI 树节点；② 胜利画面期间游戏处于 paused,常规事件在 pause 下会被调度器跳过，必须用绕过 pause 的强制计时器；③ 最隐蔽的一个是方法名大小写:get_UIE_by_id 和引擎真名 get_UIE_by_ID 差一个字母，守卫条件永远为假——那一晚 13 局 error、4 局 stuck 全是它的连锁反应(overlay 不关 → 商店卡僵尸态 → 下局启动崩溃 → 实例死 → 重启风暴)。修好后的验证判据很干净：赢下 Ante 8 的局应该正常出现在 Ante 9+ 的盲注选择界面。

4.3 可靠性工程：让夜间无人值守的 10 小时成立
#

记忆实验的真实成本是墙钟时间：一局 40-90 分钟，一个 arm = 8 训练局 + 2 评测局，没有可靠的并行就没有像样的样本量。

  • 三实例并行:3 个游戏客户端各绑独立端口和独立存档 slot(12346→slot 3、12347→slot 2、12348→slot 1),课程表分阶段爬坡(r1 单实例 → r2 双 → r3 三)，每阶段开始时 runner 自动把活实例停回主菜单、拉起缺的。
  • 写档竞争与"静置纪律":Balatro 多实例共享存档目录，一个实例在对局中(频繁写档)时冷启动另一个实例，新实例几乎必崩——canvas 竞争让它在加载期蓝屏：进程活着、端口死了，从外面看就是"重启超时"。所有冷启动路径都必须遵守纪律：先把其他实例停回主菜单静置。这个纪律我们最初只写在了阶段切换的路径上，错误恢复路径没写——一个晚上 9 局里 6 局 error 教会了我们补上(冷启动前强制 park 其他车道)。
  • 僵尸回收与两层 watchdog:崩溃的实例进程不死只是失联，反复重试会堆积僵尸(最严重一晚堆到 17 个)。回收器的判定是"不监听任何车道端口且启动超过 90 秒"(90 秒正好等于健康等待窗，窗外还不监听 = 已崩)；系统层 watchdog 每 10 分钟扫僵尸 + 按 watchdog-state 自动重启死掉的 runner,LLM 层定时任务做需要判断力的盯盘。

4.4 给思考模型松绑
#

单步超时从 120 秒放宽到 360 秒，思考默认开启。长尾一步思考几分钟属于正常现象，不再被 abort 重试。

5. 结果
#

改造是分两晚落地的，恰好形成一组对照:

修复前(8 月 20 日夜)修复后(8 月 21 日夜)
infrastructure error13 局 error + 4 局 stuck(autoendless bug 连坐)0 error(10/10 局完整)
Ante 上限全部卡在 Ante 8(64.x 分)4 局 Ante 10+,1 局打到 Ante 12(score 99.8)
训练曲线被故障淹没18.7 → 76.7 → 81.0(三阶段均分)
eval(冻结攻略)—38.6(两局均死在 Ante 4)

几点解读:

  1. 18.7 → 81.0 的训练曲线说明经验确实可以沉淀:第一局(冷启动,无攻略)和第八局之间是 4 倍多的分数差，同模型、同种子池。攻略从 1368 字符长到 2527 字符，内容从"注意小丑牌协同"进化到"Ante 8+ 必须把平铺 Mult 换成指数 xMult、经济牌是临时脚手架"。
  2. 那局 99.8 是整个项目(包括公共榜)的第一局通关，非法操作只有 1 次。endless 这条路打通后，模型的真实上限第一次被看到。
  3. eval 掉到 38.6 是当前最诚实的数字：换上新种子，模型立刻死回 Ante 4。学到的东西有多少是"泛化的打法"、多少是"对训练种子的过拟合"，是接下来要用对照实验回答的问题。

6. 结语
#

榜单上的"模型只能打到 Ante 5",拆开看是三层东西叠在一起：模型的真实水平、评测架构的记忆缺失、以及一条通关之后没人走过的 endless 路。后两层不是模型的问题，但它们实实在在压住了所有人的分数上限。

把它们拆掉之后剩下的问题反而更有意思了：当模型可以积累经验，什么样的记忆结构最有利于它进步? 全量注入一份越来越长的攻略，还是按局面取用相关的碎片经验？这是我们接下来准备用对照实验回答的问题。

附：环境与成本
#

  • Windows 跑真实游戏(Steam 版 + Lovely 注入 + 4 个 mod),WSL2 跑 runner,attach 模式;
  • 单局成本：约 40-90 分钟、66 万 token(含思考);
  • 一个完整 arm(8 训练 + 2 评测)双车道并行约 6 小时;
  • 所有对局逐 step 落 SQLite(pre-move 全量状态 + reasoning + 合法性标记)，经验挖掘和复盘都有完整原料。
